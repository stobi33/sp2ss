1-port vs 2-port

Where to cut the PDN

The port count is not a modelling convenience — it decides whether the voltage regulator is frozen inside your impedance or simulated as a live block beside it.

Same physical network, two different places to draw the model boundary. Everything the boundary encloses becomes a fixed, linear Z(s); everything outside it stays a live model your testbench simulates.

The surprise

A linear VRM collapses back to 1-port — exactly

Wire up figure 2's bottom row with a VRM that is just a source behind a fixed output impedance, and solve the two equations. The port-2 current drops out and you are left with

v₀ = i₀·( Z₁₁ − Z₁₂Z₂₁/(Z₂₂ + Z_vrm) )  +  V_src·Z₁₂/(Z₂₂ + Z_vrm)

— the first bracket being precisely the terminated 1-port impedance. This is not an approximation. Building both models through the full pipeline and comparing them:

So "my testbench has a VRM" is not by itself a reason to go 2-port. Any VRM you can describe as a linear output impedance — however elaborate — folds into Z_in with no loss. What forces the 2-port is a VRM with behaviour: state you are simulating that the impedance cannot represent.

Go 1-port
  • One aggregate die load, one rail observed at the same node
  • VRM is a fixed linear output impedance (fold it in via the termination formula)
  • You care about first and second droop, where the VRM is irrelevant anyway
Go 2-port
  • VRM control loop you are verifying — compensation, remote sense, loop bandwidth
  • DVFS setpoint steps, current limiting, phase shedding, mode transitions
  • Two load domains whose droop cross-couples — that coupling is Z₁₂
  • You drive at one node and observe at another
The trap

Don't close a loop around a 1-port

The failure mode worth naming: taking Z₁₁ and instantiating a VRM model beside it. The regulator is then present twice — once frozen into the impedance, once live — and the droop it computes is wrong in a way that looks plausible. Below 10 MHz the two terminations differ by 40–70%, which is exactly the band a VRM loop operates in.

And mind the algebraic loop

In the 2-port case, v_p1[n] depends on i_p1[n] through the feedthrough term Dd. If your VRM computes its output current from the port voltage in the same timestep, that is a same-cycle loop and the simulator will either complain or silently resolve it wrong.

The clean fix is physical rather than numerical: give the VRM model its output inductor as a state. An inductor current cannot change instantaneously, so i_p1[n] comes from the state and depends only on v_p1[n−1] and earlier. The loop is broken by the same component that breaks it in silicon.

// VRM output stage — i_p1 is a state, so no same-cycle dependence on v_p1
always_ff @(posedge clk) begin
    i_L   <= i_L + (TS/L_OUT) * (v_sw - v_p1 - R_OUT*i_L);
    v_p1_d <= v_p1;              // sensed one sample later
end
assign i_p1 = i_L;
